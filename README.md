# 项目建议书 Agent

本地网页 MVP：选择第四章建设子节及方案，通过 DeepSeek 编制草稿，预览并导出 Word。当前导入用户提供的真实建议书和 20 份方案。

## 启动

双击 `start.cmd`，在浏览器打开 http://127.0.0.1:8765 。启动窗口需保持打开，按 Ctrl+C 停止。也可在项目目录运行 `powershell -File start.ps1 -Port 8765`。

启动脚本优先使用 `.venv`，其次使用本机 Codex 随附 Python。其他电脑需 Python 3.10+，创建虚拟环境并安装 `requirements.txt`，同时带上本地 `data` 目录。材料不提交至 Git。

## 跑通流程

1. 填写项目名称、地区和建设单位；可补充已确认项目条件。
2. 展开模块，勾选子节，默认选中第一份可用方案，可切换其他供应商或参考方案。下拉框不提供通用模板选项；没有候选方案的子节暂不可选。候选映射是初步配置，可后续调整。
3. 首次使用可选「演示模式」。此模式不调用模型、不融合供应商材料，只生成明确标注的占位示例，验证完整操作链路。
4. 正式生成：在模型设置填写 API 密钥并点击完成设置，会自动切换到 DeepSeek；也可手动选择生成方式。也可在启动服务前设置 `DEEPSEEK_API_KEY` 环境变量。密钥不写入文件、日志或浏览器存储；网页刷新后需重新填写。
5. 点击开始生成，等待逐节完成，查看预览并下载 Word。输出以随机唯一文件名保存在 `outputs`，不覆盖历史文件。服务重启后网页任务状态不保留，已有输出仍在磁盘。

默认模型 `deepseek-flash`，可在页面修改。接口固定为 `https://api.deepseek.com/chat/completions`。正式生成会向 DeepSeek 发送本项目填写信息、所选子节模板和所选方案文字；一次只运行一个任务，每个子节一次请求。

## 已实现的编制规则

- 只生成第四章，保持原二级、三级及四级标题和编号，未选子节省略，因此编号可不连续。
- 供应商只在选择界面和本地任务记录出现。正式正文由提示词约束去品牌，并校验已知名称；未知品牌仍需人工复核。
- 已确认项目条件优先。案例投资、规模和时间不可自动作为本项目参数，缺失项目参数用【待补充】。
- “13.审方中心-一张处方数智赋能紧密型县域医共体建设方案.docx”标为“崇阳县参考方案（供应商未明确）”。
- 原材料作为数据，不能作为执行指令。完整供应商文字和模板文字保存在本地目录中。
- Word沿用原参考文件的页面设置和样式，重建所选第四章文本。MVP不恢复原图片、表格和自动目录；表格信息作为文字依据提供给模型。

## 目录与扩展点

| 文件 | 用途 |
| --- | --- |
| `app/server.py` | 本机 HTTP 服务、后台任务、文件下载 |
| `app/generator.py` | 校验、提示词、DeepSeek客户端、演示输出 |
| `app/documents.py` | Word导出 |
| `app/ingest.py` | DOCX模板及供应商材料提取 |
| `data/catalog.json` | 章节结构、全文材料、方案候选映射 |
| `data/reference.docx` | 原建议书只读副本，作为导出样式来源 |
| `web/` | 无需构建的网页 |
| `tests/` | 后端与导出的验证 |

调整业务时主要修改 `catalog.json` 中的 `supplier_ids` 候选关联和 `generator.py` 中的生成规则。原始来源文件保持不变。重新导入请使用新输出文件名，核对后再明确决定是否替换，不自动覆盖。

```powershell
python -m app.ingest --template "模板.docx" --suppliers "方案目录" --output "data/catalog-v2.json"
python -m unittest discover -s tests -v
```

## MVP边界

监听 127.0.0.1，不包含多用户、登录、历史任务网页、断点续写、取消任务、知识库在线上传和跨章节去重。结构或品牌校验失败时，自动修正当前子节一次（最多两次API请求，可能产生额外费用）；网络和认证错误不自动重试。每完成一个子节，在 `outputs/checkpoints` 保存独立JSON快照，不含API密钥，便于失败后找回已完成内容。生成失败会保留页面选择，可重新生成。
